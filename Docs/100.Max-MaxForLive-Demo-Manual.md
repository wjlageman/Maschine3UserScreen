# Max / MaxForLive Demo Manual

This patch forms a demonstration and development environment for the Maschine3UserScreen Javascript / Sciter application. The patch demonstrates how an external application can communicate with the Maschine MK3 user screens through OSC.

## 1. Purpose of the Demo

The demo shows how a Max or MaxForLive patch can:

- send OSC messages to the Javascript application
- modify widget states
- request layout information
- read the current UI state
- inspect widgets and containers
- receive menu, hover, and click events
- dynamically control the Maschine MK3 displays

## 2. General Architecture

The patch communicates via OSC over UDP with the Maschine3UserScreen application. The C++ application handles the USB, display, and controller interfaces. The Javascript / Sciter layer handles widgets, layout, and rendering.

```text
Max / MaxForLive
→ OSC over UDP
→ Maschine3UserScreen.exe
→ Javascript / Sciter
→ Widgets and rendering
→ Maschine MK3 displays
```

## 3. Important Components of the Patch

| Component | Type | Function |
|-----------|------|----------|
| dict maschine3 | dict | Contains the current global UI state. |
| dict container | dict | Contains container information. |
| route loaded | route | Detects screen loaded events. |
| print PAGE_LOADED | debug | Shows when a template has been loaded. |
| p controls | subpatch | Inspection of low-level control signals. |
| ---osc_update | send/receive | Internal distribution of OSC updates. |
| ---widget_menu | send/receive | Communication related to widget menus. |
| ---region_menu | send/receive | Communication related to region menus. |
| ---edited_widget | send/receive | Widget inspection and editing. |
| ---maschine3 | send/receive | Main communication with Maschine3 state. |

## 4. Loaded Event and Screen Lifecycle

When a new screen is loaded, the Javascript application sends a loaded event:

```text
/maschine3/screen loaded "template" "title"
```

The patch uses `route loaded` to capture this event. Only after this event has been received may the current structure or `ui_state` be requested.

## 5. Use of Dict Objects

The patch uses multiple Max dict objects as a local cache of the current UI state.

- `dict maschine3`: complete global state
- `dict container`: current container information
- widget dictionaries: temporary widget inspection
- `edited_widget` / `edited_container`: editing and updates

This allows the patch to quickly inspect widgets, modify properties, and send OSC updates back without requesting the complete state again.

## 6. OSC Updates

The patch processes OSC updates through send/receive objects such as:

```text
---osc_update
---maschine3
---widget_menu
---region_menu
```

This allows different parts of the patch to respond independently to changes in widgets, containers, and menus.

## 7. Low-Level Controls

The patch contains a separate subpatch for low-level Maschine control events.

The subpatch `p controls` can be opened through the button **Open low level signals**.

Developers can directly inspect:

- button events
- encoder events
- hover events
- click events
- touch events
- raw control signals

## 8. Debugging and Inspection

The patch contains several print objects and debug routes for inspecting OSC communication.

```text
print PAGE_LOADED
print CLICK
print HOVER
```

These debug objects make it easier to follow widget behaviour and OSC events during development.

## 9. Relationship with HTM Layouts

The patch works together with the `.htm` templates of the Javascript application.

Widgets in the Max patch indirectly reference OSC addresses that are constructed from the `.htm` layout structure.

```text
/split/left/dials/dial-1
/split/right/buttons/play
```

When a new template is loaded, the complete widget structure may change. The patch must therefore request the current structure and `ui_state` again.

## 10. Practical Workflow

1. Start `Maschine3UserScreen.exe`
2. Load an `.htm` template
3. Wait for the loaded event
4. Request the structure or `ui_state`
5. Inspect widgets and containers
6. Send OSC updates to widgets
7. Observe rendering on the Maschine MK3 displays

## 11. Design Philosophy

The patch follows the same state-based design as the Javascript application.

- State is the single source of truth
- Rendering reflects only the current state
- No hidden corrections or implicit modifications
- Explicit OSC updates modify widget states
- The layout structure is fixed after compilation

## 12. Summary

This Max / MaxForLive patch forms a development and demonstration environment for the Maschine3UserScreen architecture. The patch demonstrates how external software can manage widgets, layouts, and states of the Maschine MK3 user screens through OSC.

The patch combines:

- OSC communication
- widget inspection
- state management
- layout inspection
- debugging
- live rendering to Maschine MK3 displays
